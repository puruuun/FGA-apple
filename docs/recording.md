# 호스트 녹화 형식

`host battle`에 `--record=<폴더>`를 붙이면 한 번의 실행을 폴더 하나에 기록합니다. Rust 코어를 Kotlin 원본과 비교하기 위한 입력이며(`docs/design/0001-rust-core.md` 5절), 이 문서는 읽는 쪽을 만들 수 있을 만큼만 정확하게 형식을 적습니다. 녹화 형식 버전은 `1`입니다.

```
host battle configs/first-test.json --dry-run --record=build/rec-check
```

녹화에는 계정 화면이 들어 있으므로 저장소에 넣지 않습니다. `<폴더>`에 `events.jsonl`이 이미 있으면 덮어쓰지 않고 시작하지 않습니다.

## 폴더 구성

```
<폴더>/
  meta.json
  events.jsonl
  frames/
    00000000.jpg
    00000200.jpg
    ...
```

## 시간

모든 시각은 녹화를 시작한 순간부터 흐른 밀리초이며, 프레임 파일 이름과 이벤트의 `t`가 같은 시계(`System.nanoTime` 기반 단조 시계, 녹화 시작 시 0)를 씁니다. 벽시계 시각은 기록하지 않습니다.

## frames/

- 파일 이름은 `<t_ms>.jpg`이고 `t_ms`는 8자리로 0을 채운 밀리초입니다. 예: `00001234.jpg`. 8자리를 넘으면(약 27시간 이후) 자릿수가 늘어나므로, 읽는 쪽은 자릿수를 가정하지 말고 숫자로 해석하고 정렬해야 합니다.
- 내용은 화면 서버가 보낸 JPEG 바이트를 다시 인코딩하지 않고 그대로 저장한 것입니다.
- 별도 스레드가 약 200ms마다 화면 서버(`/frame`)에 요청합니다. 받은 바이트가 직전에 저장한 프레임과 완전히 같으면 저장하지 않습니다. 따라서 프레임 사이의 간격은 일정하지 않고, 어떤 시각 `T`의 화면은 `t_ms <= T`인 마지막 프레임입니다.
- 파일 이름의 `t_ms`는 그 바이트를 다 받은 시각입니다. 화면이 실제로 바뀐 시각은 그보다 조금 앞설 수 있습니다.
- 첫 프레임은 항상 저장됩니다. 프레임이 하나도 없는 구간은 화면이 바뀌지 않은 구간입니다.

## events.jsonl

UTF-8, 한 줄에 JSON 객체 하나, 줄 끝은 `\n`입니다. 모든 객체에 다음 두 키가 있고 이 순서로 나옵니다.

| 키 | 형 | 뜻 |
| --- | --- | --- |
| `t` | 정수 | 호출이 시작된 시각(ms). 호출이 끝난 시각이 아닙니다. 탭 뒤에는 대기 시간이 붙으므로 이 값이 더 이릅니다. |
| `type` | 문자열 | 아래 표의 종류 |

이벤트는 호출이 끝난 뒤에 기록되므로, 파일의 줄 순서는 호출이 끝난 순서이고 `t`가 항상 단조 증가하지는 않을 수 있습니다. 같은 스레드의 호출은 서로 겹치지 않으므로 실제로는 거의 증가합니다. 순서가 필요하면 줄 순서를 쓰세요.

좌표는 모두 화면 픽셀(`meta.json`의 `screenWidth` x `screenHeight` 기준)이며, 제스처 서비스가 스크립트에서 받은 값 그대로입니다. 보드로 보내는 0~32767 좌표가 아닙니다.

| `type` | 추가 키 | 뜻 |
| --- | --- | --- |
| `screenshot` | 없음 | 스크립트가 화면을 요청했습니다. 픽셀은 없습니다. |
| `tap` | `x`, `y`, `times` | `times`번 연속 탭 |
| `swipe` | `x1`, `y1`, `x2`, `y2` | `(x1,y1)`에서 `(x2,y2)`로 스와이프 |
| `scroll` | `x1`, `y1`, `x2`, `y2` | 끝에서 멈춘 뒤 떼는 스크롤 |
| `pinch` | `ax1`, `ay1`, `ax2`, `ay2`, `bx1`, `by1`, `bx2`, `by2`, `durationMs`, `performed` | 두 손가락. A는 `(ax1,ay1)`에서 `(ax2,ay2)`로, B는 `(bx1,by1)`에서 `(bx2,by2)`로. `performed`는 호스트가 실제로 수행했는지이며, 현재 호스트는 핀치를 수행하지 않으므로 `false`입니다. |
| `notify` | `text` | 스크립트의 알림. `text`는 콘솔에 찍히는 줄 그대로(`[notify] ...`)입니다. |
| `log` | `text` | 스크립트의 로그. `text`는 콘솔에 찍히는 줄 그대로(`[log] ...`)입니다. |
| `exit` | `reason`, `runs` | 스크립트 종료. `reason`은 콘솔의 `종료:` 뒤 문자열, `runs`는 완료한 실행 횟수입니다. 파일의 마지막 줄입니다. |

`--dry-run`과 함께 써도 같은 이벤트가 기록되며, 이 경우 보드에는 아무것도 보내지 않았습니다.

예:

```
{"t":1520,"type":"screenshot"}
{"t":1810,"type":"tap","x":1310,"y":603,"times":1}
{"t":2410,"type":"notify","text":"[notify] CEGet"}
{"t":91200,"type":"exit","reason":"RunLimitReached","runs":1}
```

`exit` 줄이 없으면 실행이 비정상적으로 끝난 것입니다(프로세스 강제 종료 등). 그런 녹화도 `exit` 앞까지는 읽을 수 있습니다.

## meta.json

한 줄 JSON 객체입니다.

| 키 | 형 | 뜻 |
| --- | --- | --- |
| `formatVersion` | 정수 | `1` |
| `screenWidth`, `screenHeight` | 정수 | 호스트 설정의 화면 크기 |
| `gameServer` | 문자열 | 게임 서버 (`Kr`, `En` 등) |
| `battleConfig` | 객체 | 불러온 전투 설정의 키-값 지도. 설정 파일(또는 `--fga`로 가져온 내보내기)의 `battleConfig` 객체를 값 변환 없이 그대로 담습니다. 기본값으로 채워지는 키는 들어 있지 않습니다. |
| `fgaCommit` | 문자열 또는 `null` | `fga` 서브모듈의 커밋. `git`으로 알아내지 못하면 `null` |

## 실패

화면 파일이나 이벤트 줄을 쓰지 못하거나 화면 서버에서 녹화용 화면을 받지 못하면 호스트는 스크립트를 멈추고 이유를 출력한 뒤 종료 코드 1로 끝납니다. 구멍 난 녹화는 없는 것보다 나쁘기 때문에 이 오류를 무시하지 않습니다. 이 경우 폴더의 내용은 쓸 수 없는 것으로 보세요.

## 읽는 쪽이 지킬 것

- `events.jsonl`의 모르는 `type`이나 모르는 키는 무시하지 말고 형식 버전이 올랐는지 확인하세요.
- 프레임과 이벤트를 합칠 때는 `t_ms`와 `t`를 같은 시간축으로 비교합니다.
- `tap`의 `t`는 호출이 시작된 시각이므로, 그 탭 직전 화면은 `t_ms <= t`인 마지막 프레임입니다.
